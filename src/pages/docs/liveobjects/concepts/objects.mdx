LiveObjects enables you to store shared data as "objects" on a channel, allowing your application data to be synchronized across multiple users and devices in realtime. This document explains the key concepts you need to know when working with objects.

## Primitive types <a id="primitive-types"/>

Primitive types are the fundamental data types that can be stored in a collection type. Currently, the only supported collection type is a [LiveMap](/docs/liveobjects/map).

LiveObjects supports the following primitive types:

<If lang="javascript">
* `string`
* `number`
* `boolean`
* `bytes`
* JSON arrays or objects

<Aside data-type='note'>
`number` is a double-precision floating-point number, which is the same as JavaScript's [`number`](https://developer.mozilla.org/en-US/docs/Glossary/Number) type.
</Aside>
</If>

<If lang="swift">
* `String`
* `Double`
* `Bool`
* `Data`
* JSON arrays or objects
</If>

<If lang="java">
* `String`
* `Number` (Double, Integer, Float, etc.)
* `Boolean`
* `byte[]` (binary data)
* JSON arrays or objects (`JsonArray`, `JsonObject`)
</If>

## Object types <a id="object-types"/>

LiveObjects provides specialized object types to model your application state. These object types are designed to be conflict-free and eventually consistent, meaning that all operations on them are commutative and converge to the same state across all clients.

### LiveMap <a id="livemap"/>

[LiveMap](/docs/liveobjects/map) is a key/value data structure similar to a <If lang="javascript">dictionary or JavaScript [Map](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Map)</If>
<If lang="swift">`Dictionary`</If><If lang="java">Java `Map`</If>:

* Keys must be strings
* Values can be primitive types, JSON-serializable objects or arrays, or [references](#composability) to other objects
* Supports `set` and `remove` operations
* Concurrent updates to the same key are resolved using last-write-wins (LWW) semantics

<Code>
```javascript
// Create and assign a LiveMap
await rootObject.set('settings', LiveMap.create({
  theme: 'dark',
  notifications: true
}));

// Access via path
const settings = rootObject.get('settings');
await settings.set('fontSize', 14);
```

```swift
// rootObject obtained from channel.object.get()

// Create a LiveMap with initial entries
let initialSettings = LiveMap.create(entries: [
    "theme": "dark",
    "notifications": true,
])

// Assign it to the 'settings' key on the channel object
try await rootObject.set(key: "settings", value: .liveMap(initialSettings))

// Access and update it through its path
let settings = rootObject.get(key: "settings").asLiveMap()
try await settings.set(key: "fontSize", value: 14)
```

```java
// rootObject obtained from channel.object.get()

// Create a LiveMap with initial entries
LiveMap initialSettings = LiveMap.create(Map.of(
    "theme", LiveMapValue.of("dark"),
    "notifications", LiveMapValue.of(true)));

// Assign it to the 'settings' key on the channel object
rootObject.set("settings", LiveMapValue.of(initialSettings)).join();

// Access and update it through its path
LiveMapPathObject settings = rootObject.get("settings").asLiveMap();
settings.set("fontSize", LiveMapValue.of(14)).join();
```
</Code>

### LiveCounter <a id="livecounter"/>

[LiveCounter](/docs/liveobjects/counter) is a numeric counter type:

* The value is a double-precision floating-point number
* Supports `increment` and `decrement` operations

<Code>
```javascript
// Create and assign a LiveCounter
await rootObject.set('visits', LiveCounter.create(0));

// Access via path
const visits = rootObject.get('visits');
await visits.increment(1);
```

```swift
// Create a LiveCounter with initial value 0
let visitsCounter = LiveCounter.create(initialCount: 0)

// Assign it to the 'visits' key on the channel object
try await rootObject.set(key: "visits", value: .liveCounter(visitsCounter))

// Access and update it through its path
let visits = rootObject.get(key: "visits").asLiveCounter()
try await visits.increment(amount: 1)
```

```java
// Create a LiveCounter with initial value 0
LiveCounter visitsCounter = LiveCounter.create(0);

// Assign it to the 'visits' key on the channel object
rootObject.set("visits", LiveMapValue.of(visitsCounter)).join();

// Access and update it through its path
LiveCounterPathObject visits = rootObject.get("visits").asLiveCounter();
visits.increment(1).join();
```
</Code>

## Channel object <a id="channel-object"/>

The channel object is a special `LiveMap` instance which:

* Implicitly exists on a channel and does not need to be created explicitly
* Has the special [objectId](#object-ids) of `root`
* Cannot be deleted
* Serves as the [entry point](#reachability) for accessing all other objects on a channel

<If lang="javascript">
Access the channel object using `channel.object.get()`, which returns a [`PathObject`](/docs/liveobjects/concepts/path-object) that resolves to the root `LiveMap`:
</If>
<If lang="swift">
Access the channel object using `channel.object.get()`, which returns a [`LiveMapPathObject`](/docs/liveobjects/concepts/path-object?lang=swift) resolving to the root `LiveMap`. The `channel.object` accessor is available once you register the LiveObjects plugin through `clientOptions.plugins`:
</If>
<If lang="java">
Access the channel object using `channel.object.get()`, which returns a future that completes with a [`LiveMapPathObject`](/docs/liveobjects/concepts/path-object?lang=java) resolving to the root `LiveMap`:
</If>

<Code>
```javascript
// Get the channel object.
// This implicitly attaches to the channel if not already attached.
// The promise resolves when the channel object data has been synchronized to the client.
const rootObject = await channel.object.get();

// Use it like any other LiveMap
await rootObject.set('app-version', '1.0.0');
await rootObject.set('config', LiveMap.create({
  apiUrl: 'https://api.example.com'
}));
```

```swift
// Implicitly attaches the channel; suspends until the state is synchronized
let rootObject = try await channel.object.get()

// Use it like any other LiveMap
try await rootObject.set(key: "app-version", value: "1.0.0")

// Create a config map
let config = LiveMap.create(entries: [
    "apiUrl": "https://api.example.com",
])

// Assign it to the 'config' key on the channel object
try await rootObject.set(key: "config", value: .liveMap(config))
```

```java
// Implicitly attaches the channel; the future completes once state is SYNCED
LiveMapPathObject rootObject = channel.object.get().join();

// Use it like any other LiveMap
rootObject.set("app-version", LiveMapValue.of("1.0.0")).join();

// Create a config map
LiveMap config = LiveMap.create(Map.of(
    "apiUrl", LiveMapValue.of("https://api.example.com")));

// Assign it to the 'config' key on the channel object
rootObject.set("config", LiveMapValue.of(config)).join();
```
</Code>

<Aside data-type='note'>
Calling `channel.object.get()` implicitly attaches to the channel if not already attached and waits for the LiveObjects state to [synchronize](/docs/liveobjects/concepts/synchronization).
</Aside>

## PathObject <a id="pathobject"/>

[`PathObject`](/docs/liveobjects/concepts/path-object) provides a path-based API for interacting with objects at specific locations. The path is evaluated when a method is called, resolving to whatever instance exists at that location:

<Code>
```javascript
// Get the channel object
const rootObject = await channel.object.get();

// Navigate to nested paths
const theme = rootObject.get('settings').get('theme');

// The path evaluates to an object instance when you call a method on it
await rootObject.get('visits').increment(5);
await rootObject.get('settings').set('notifications', true);
```

```swift
// Get the channel object
let rootObject = try await channel.object.get()

// Purely navigational - nothing is resolved yet
let visits = rootObject.get(key: "visits")

// Resolution happens when a terminal method is called
try await visits.asLiveCounter().increment(amount: 5)
try await rootObject.get(key: "settings").asLiveMap().set(key: "notifications", value: true)
```

```java
// Get the channel object
LiveMapPathObject rootObject = channel.object.get().join();

// Purely navigational - nothing is resolved yet
PathObject visits = rootObject.get("visits");

// Resolution happens when a terminal method is called
visits.asLiveCounter().increment(5).join();
rootObject.get("settings").asLiveMap().set("notifications", LiveMapValue.of(true)).join();
```
</Code>

Use `PathObject` for:
- Location-based operations (most common use case)
- Resilient code that works regardless of instance replacements
- Simple navigation through your data structure

See the [PathObject documentation](/docs/liveobjects/concepts/path-object) for details.

## Instance <a id="instance"/>

[`Instance`](/docs/liveobjects/concepts/instance) provides direct access to a specific object instance, which is identified by a unique [object ID](/docs/liveobjects/concepts/objects#object-ids).

<Code>
```javascript
// Get the channel object
const rootObject = await channel.object.get();

// Navigate to nested paths and get the instance
const themeInstance = rootObject.get('settings').get('theme').instance(); // undefined only if nothing exists at the path

// Work directly with the instance
await rootObject.get('visits').instance()?.increment(5);
await rootObject.get('settings').instance()?.set('notifications', true);
```

```swift
// Get the channel object
let rootObject = try await channel.object.get()

// Navigate to nested paths and get the instance
let themeInstance = try rootObject.get(key: "settings").asLiveMap().get(key: "theme").instance()

// Work directly with the instance.
// instance() returns nil only if nothing exists at the path
if case .liveCounter(let visitsInstance)? = try rootObject.get(key: "visits").instance() {
    try await visitsInstance.increment(amount: 5)
}

if case .liveMap(let settingsInstance)? = try rootObject.get(key: "settings").instance() {
    try await settingsInstance.set(key: "notifications", value: true)
}
```

```java
// Get the channel object
LiveMapPathObject rootObject = channel.object.get().join();

// Navigate to nested paths and get the instance
Instance themeInstance = rootObject.get("settings").asLiveMap().get("theme").instance();

// Work directly with the instance
Instance visitsInstance = rootObject.get("visits").instance(); // null only if nothing exists at the path
if (visitsInstance != null) {
    visitsInstance.asLiveCounter().increment(5).join();
}

Instance settingsInstance = rootObject.get("settings").instance();
if (settingsInstance != null) {
    settingsInstance.asLiveMap().set("notifications", LiveMapValue.of(true)).join();
}
```
</Code>

Use `Instance` for:
- Tracking specific objects as they move through your data structure
- Detecting when a specific object is deleted

See the [Instance documentation](/docs/liveobjects/concepts/instance) for details.

</If>

## Composability <a id="composability"/>

LiveObjects enables you to build complex, hierarchical data structures through composability.

Specifically, a [LiveMap](/docs/liveobjects/map) can store references to other `LiveMap` or `LiveCounter` object instances as values. This allows you to create nested hierarchies of data.

<Code>
```javascript
// Create a nested structure in a single operation
await rootObject.set('profile', LiveMap.create({
  name: 'Alice',
  preferences: LiveMap.create({
    theme: 'dark',
    fontSize: 14
  }),
  activity: LiveCounter.create(0)
}));

// Resulting structure:
// rootObject (LiveMap - channel object)
// └── profile (LiveMap)
//     ├── name: "Alice" (string)
//     ├── preferences (LiveMap)
//     │   ├── theme: "dark" (string)
//     │   └── fontSize: 14 (number)
//     └── activity (LiveCounter)

// Access and update nested values via paths
await rootObject.get('profile').get('activity').increment(5);
await rootObject.get('profile').get('preferences').set('theme', 'light');
```

```swift
// Create a map for the nested preferences
let preferences = LiveMap.create(entries: [
    "theme": "dark",
    "fontSize": 14,
])

// Create a counter for the nested activity
let activity = LiveCounter.create(initialCount: 0)

// Compose the profile entries, referencing the nested objects
let profile = LiveMap.create(entries: [
    "name": "Alice",
    "preferences": .liveMap(preferences),
    "activity": .liveCounter(activity),
])

// Assign the profile map to the channel object.
// The whole tree publishes as a single operation.
try await rootObject.set(key: "profile", value: .liveMap(profile))

// Resulting structure:
// rootObject (LiveMap - channel object)
// └── profile (LiveMap)
//     ├── name: "Alice" (string)
//     ├── preferences (LiveMap)
//     │   ├── theme: "dark" (string)
//     │   └── fontSize: 14 (number)
//     └── activity (LiveCounter)

// Update nested values through their paths
try await rootObject.at(path: "profile.activity").asLiveCounter().increment(amount: 5)
try await rootObject.at(path: "profile.preferences").asLiveMap().set(key: "theme", value: "light")
```

```java
// Create a map for the nested preferences
LiveMap preferences = LiveMap.create(Map.of(
    "theme", LiveMapValue.of("dark"),
    "fontSize", LiveMapValue.of(14)));

// Create a counter for the nested activity
LiveCounter activity = LiveCounter.create(0);

// Compose the profile entries, referencing the nested objects
Map<String, LiveMapValue> profileData = Map.of(
    "name", LiveMapValue.of("Alice"),
    "preferences", LiveMapValue.of(preferences),
    "activity", LiveMapValue.of(activity));

// Create the profile map from the composed entries
LiveMap profile = LiveMap.create(profileData);

// Assign the profile map to the channel object.
// The whole tree publishes as a single operation.
rootObject.set("profile", LiveMapValue.of(profile)).join();

// Resulting structure:
// rootObject (LiveMap - channel object)
// └── profile (LiveMap)
//     ├── name: "Alice" (string)
//     ├── preferences (LiveMap)
//     │   ├── theme: "dark" (string)
//     │   └── fontSize: 14 (number)
//     └── activity (LiveCounter)

// Update nested values through their paths
rootObject.at("profile.activity").asLiveCounter().increment(5).join();
rootObject.at("profile.preferences").asLiveMap().set("theme", LiveMapValue.of("light")).join();
```
</Code>

<Aside data-type='note'>
Internally, a `LiveMap` instance only stores a _reference_ to another object (by its [object ID](#object-ids)), rather than the value of the nested object itself. <If lang="javascript,java">When using a client SDK, object references are automatically resolved when resolving paths using the [PathObject](/docs/liveobjects/concepts/path-object), or when navigating the object tree using the `Instance.get()` [method](/docs/liveobjects/concepts/instance#get).</If><If lang="swift">When using a client SDK, object references are automatically resolved when resolving paths using the [PathObject](/docs/liveobjects/concepts/path-object?lang=swift), or when navigating the object tree using the Instance `get(key:)` [method](/docs/liveobjects/concepts/instance?lang=swift#get).</If>
</Aside>

## Reachability <a id="reachability"/>

All objects must be reachable from the channel object (directly or indirectly). Objects that cannot be reached from the channel object will eventually [be deleted](/docs/liveobjects/lifecycle#objects-deleted).

<If lang="javascript,swift,java">
When you replace or remove an object reference, it may become unreachable and will eventually be [deleted](/docs/liveobjects/lifecycle#objects-deleted):

<Code>
```javascript
// Create and assign a counter
await rootObject.set('visits', LiveCounter.create(0));

// Get the counter instance to track it
const oldCounter = rootObject.get('visits').instance();

if (oldCounter) {
  oldCounter.subscribe(({ object, message }) => {
    if (message?.operation.action === 'object.delete') {
      console.log('Counter was deleted');
    }
  });

  // Replace with a new counter - old counter becomes unreachable
  await rootObject.set('visits', LiveCounter.create(0));
  // The subscription will fire with the delete notification
}
```

```swift
// Create and assign a counter
let visitsCounter = LiveCounter.create(initialCount: 0)
try await rootObject.set(key: "visits", value: .liveCounter(visitsCounter))

// Get the counter instance to track it
if case .liveCounter(let oldCounter)? = try rootObject.get(key: "visits").instance() {
    try oldCounter.subscribe { event in
        if event.message?.operation.action == .objectDelete {
            print("Old counter was deleted")
        }
    }
}

// Replace with a new counter - the old instance becomes unreachable
let replacementCounter = LiveCounter.create(initialCount: 0)
try await rootObject.set(key: "visits", value: .liveCounter(replacementCounter))
// The subscription will fire with the delete notification
```

```java
// Create and assign a counter
LiveCounter visitsCounter = LiveCounter.create(0);
rootObject.set("visits", LiveMapValue.of(visitsCounter)).join();

// Get the counter instance to track it
Instance oldCounter = rootObject.get("visits").instance();
if (oldCounter != null) {
    oldCounter.asLiveCounter().subscribe(event -> {
        ObjectMessage msg = event.getMessage();
        if (msg != null && msg.getOperation().getAction() == ObjectOperationAction.OBJECT_DELETE) {
            System.out.println("Old counter was deleted");
        }
    });
}

// Replace with a new counter - the old instance becomes unreachable
LiveCounter replacementCounter = LiveCounter.create(0);
rootObject.set("visits", LiveMapValue.of(replacementCounter)).join();
// The subscription will fire with the delete notification
```
</Code>
</If>

<Aside data-type='note'>
When an object becomes unreachable or a map entry is removed, it becomes a [tombstone](#tombstones).
</Aside>

## Metadata <a id="metadata"/>

Objects include metadata that helps with synchronization, conflict resolution and managing the object lifecycle.

<Aside data-type='note'>
When using a client library, metadata is handled internally. However, this information can be helpful when working directly with the [REST API](/docs/liveobjects/rest-api-usage).
</Aside>

### Object IDs <a id="object-ids"/>

Every object has a unique identifier that distinguishes it from all other objects.

<If lang="javascript,swift,java">
You can access an object's ID using the [Instance](/docs/liveobjects/concepts/instance) API:

<Code>
```javascript
const counterInstance = rootObject.get('visits').instance();

if (counterInstance) {
  const objectId = counterInstance.id;
  console.log('Object ID:', objectId);
  // e.g., "counter:J7x6mAF8X5Ha60VBZb6GtXSgnKJQagNLgadUlgICjkk@1734628392000"
}
```

```swift
if case .liveCounter(let counterInstance)? = try rootObject.get(key: "visits").instance() {
    let objectId = counterInstance.id
    print("Object ID: \(objectId)")
    // e.g., "counter:J7x6mAF8X5Ha60VBZb6GtXSgnKJQagNLgadUlgICjkk@1734628392000"
}
```

```java
Instance counterInstance = rootObject.get("visits").instance();

if (counterInstance != null) {
    String objectId = counterInstance.asLiveCounter().getId();
    System.out.println("Object ID: " + objectId);
    // e.g., "counter:J7x6mAF8X5Ha60VBZb6GtXSgnKJQagNLgadUlgICjkk@1734628392000"
}
```
</Code>
</If>

Object IDs are opaque strings that uniquely identify each object instance. The client library automatically manages object IDs and allows you to work with object references directly. However, you may specify object IDs explicitly when using the [REST API](/docs/liveobjects/rest-api-usage).

### Tombstones <a id="tombstones"/>

Tombstones are markers indicating an object or map entry has been deleted.

* A tombstone is created for an object when it becomes [unreachable](#reachability) from the channel object.
* A tombstone is created for a map entry when it is [removed](/docs/liveobjects/map#remove)

Tombstones protect against lagging clients from re-introducing a deleted value, ensuring all clients eventually converge on the same state. They are eventually garbage collected after a safe period of time.

### Timeserials <a id="timeserials"/>

When an operation message is published it is assigned a unique logical timestamp called a "timeserial".

This timeserial is stored on map entries in order to implement last-write-wins conflict resolution semantics.

Additionally, all objects store the timeserial of the last operation that was applied to the object. Since Ably operates fully independent data centers, these timeserials are stored on a per-site basis.

Timeserial metadata is used for internal purposes and is not directly exposed in client libraries. However, it can be viewed using the [REST API](/docs/liveobjects/rest-api-usage).
